# Project state

R7b accepts both local Hub origins (`localhost:5177` and `127.0.0.1:5177`), adds a content-script presence hint, and refreshes the individual access dialog. A confirmed extension PING still gates ticket issuance. The extension ID, real Chrome validation, and production TLS remain separate gates.

Hublink contains a React web app, a loopback Fastify API, and a Chrome MV3 extension scaffold. The detailed SVA research and operational destinations remain outside this portfolio repository.

R1 introduced a configurable local demo. Its brand settings and legacy public example links are stored in data/config.json through GET/PUT /api/config. JSON import/export applies only to that demo configuration. The authenticated dashboard now renders cards from PostgreSQL through GET /api/catalog; changes to the demo JSON do not publish private cards.

R2 defined the PostgreSQL schema and private contracts. R3 added local identity, persistent sessions, and attendant management. R4 added the AES-256-GCM vault, audited credential operations, and service registration. R5 added migration 003_services_visual_metadata.sql, private catalog read/write routes, card metadata, and an integrated admin card and shared-vault form. Attendants can save their own individual credentials through the existing vault route. R6 added single-use opening tickets, direct extension exchange, extension detection, local installation guidance, and manual-login fallback. R7 adds a generic assisted autofill engine for a recognized login form at the API-confirmed HTTPS destination. It never submits the form.

The API remains bound to 127.0.0.1 by default. The extension has `tabs`, `scripting`, the API loopback host, and user-approved `https://*/*` permission for dynamic destinations. The worker checks the loaded tab URL, and the content script checks its own location before filling. Credentials are short-lived JavaScript references, not securely erasable strings; no extension storage is used. R7b accepts two fixed local Hub origins and still uses a configured extension ID; stable distribution ID and production TLS remain undecided. Synthetic tests establish local engine behavior only. Installed-extension, supplier, and production behavior remain unverified. R8 operation planning and an authorized real-browser pilot are the next gates.
